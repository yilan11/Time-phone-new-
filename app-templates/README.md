# 雪落机 APP 代码交付模板

## 这份模板有什么用

让你或其他 AI 按照小手机能承载的格式制作塔罗、日历、课程表等网页 APP。这里只提供格式与空白骨架，不新增实际 APP，不替换现有 HTML，不添加桌面入口，也不修改主项目。

旁边的 `html-app-template.html` 是可复制的空白骨架。它仅包含页面结构和基础样式，没有业务功能、不访问网络、不保存数据；不是完整 APP。已做下述基础显示检查，但不等于完整兼容验收。

## 小手机能使用哪些代码

| 类型 | 通俗说明 | 当前适配方式 |
| --- | --- | --- |
| HTML | 页面文字、图片、按钮、表格等结构 | 支持；推荐交付完整 HTML 文件 |
| CSS | 颜色、布局、字体、动画 | 支持；可写进 HTML 的 style 中 |
| 原生 JavaScript | 点击、计算、抽签、日期切换、课程编辑等逻辑 | 支持；可写进 HTML 的 script 中 |
| 图片、SVG、音视频、字体 | 页面素材 | 支持浏览器可识别的格式；需要一并交付并使用相对路径，格式兼容性仍需测试 |
| localStorage / IndexedDB | 在本机浏览器保存数据 | 浏览器允许时可用；不是云端同步，需要处理失败与备份 |
| 第三方前端库 | 使用现成的网页工具 | 需要核对依赖、授权及兼容性；优先随文件本地交付 |
| React / Vue 等源码 | 需要额外处理的前端项目 | JSX、TSX、Vue 单文件组件不能当普通 HTML 直接打开；通常需要先构建成静态 HTML/CSS/JS，再适配 |
| TypeScript / Sass 等源码 | 需要转换的代码 | 先转换成浏览器可执行的 JS/CSS |
| Python、PHP、Java、Node.js 后端代码 | 需要服务器运行的程序 | 不能直接作为此静态网页中的浏览器脚本运行；如有需求需另行讨论后端 |
| API、登录、真实支付、设备能力 | 联网服务或需权限的功能 | 不等于自动支持；需核对服务端、跨域、HTTPS、权限及安全要求，另行确认 |

推荐交付：一个完整的 HTML，内含 CSS 和原生 JavaScript。图片较多时可另附 assets 文件夹。

## 如何放进小手机

当前已存在独立 HTML 的 iframe 加载方式，但没有证据表明已经做成“选择任意文件就自动安装”的功能。

通俗说：先做好一个独立网页，确认你同意接入，再由开发者把它接到对应的桌面入口。外层小手机负责返回桌面，APP 自己负责内部功能。

目前外层适配样式只针对已有容器，后续新页面仍需单独接好高度、样式及入口，不能把“可以使用 HTML”理解成“任何代码都无需适配”。iframe 主要隔离页面样式，不是可信代码的安全保证；同源脚本仍可能影响主项目，接入前需检查。

## 可以直接复制给其他 AI 的要求

从下面开始复制，并填好 APP 名称、功能与风格；不需要的项目写“无”。

---

请为“雪落机”小手机制作一个独立网页 APP，只做我明确列出的功能，不擅自增加 APP、功能、外部服务或改动已有项目。如有建议，请先提出，不要直接实施。

【APP 名称】
填写：塔罗 / 日历 / 课程表 / 其他。

【需要的功能】
1. 填写我明确要求的功能。
2. 填写我明确要求的功能。

【外观要求】
填写颜色、排版、参考图、字体及素材要求。没有明确要求的部分先询问或保持简单，不要自行重做整个设计。

【已有代码与素材】
填写：沿用我提供的 HTML 和素材 / 从空白制作。若我已提供代码，先检查和适配，不要未经同意重写或换成别的 APP。缺少素材或代码时明确告诉我，不要假装已有。

【代码格式】
- 优先交付一个完整 `.html` 文件，必须包含 doctype、html、head、body，CSS 放在 style 内，原生 JavaScript 放在 script 内。
- 提供可以保存运行的完整代码，不省略主体，不使用“此处略去”。页面可见文案用通俗中文。
- 不要求 npm、打包或终端环境；不要直接交付 JSX、TSX、Vue 单文件组件或后端源码。若确实需要这些技术，先说明并征得同意。
- 需要图片等素材时一并提供，使用相对路径；不要引用自己电脑上的绝对路径。
- 默认不用 CDN、外链字体、远程图片或其他网络依赖。确有需要先说明，并考虑网络失败时的提示。

【手机适配】
- 页面在小手机内以独立 iframe 加载，CSS 和 JS 只操作自己的页面。
- 加入移动端 viewport，优先适配 320px 至 430px 宽度，也应能在更宽视口正常显示；不写死成固定手机宽高。
- 页面整体不要产生横向溢出；日历、课程表确需多列时，优先缩放排版，仍放不下再让表格区域独立横向滚动，不要简单裁掉内容。
- 按钮便于手指点击，输入框文字建议至少 16px；内容过长可以上下滚动。软键盘出现后的可用性需要实际验收。
- 外层小手机负责返回桌面。不要使用 parent.document、top.location、history.back() 或随意改动父页面。
- iframe 内的 data-go 不会自动触发父页面导航；需要额外联动时先讨论接口，不要假设已有。
- 不自行占用全屏、拦截系统返回、申请通知或注册 Service Worker。

【数据与安全】
- 只有我要求保存的内容才保存；每个 APP 使用独立键，例如 snowfall-app-tarot-v1、snowfall-app-calendar-v1、snowfall-app-timetable-v1。
- 读写存储、解析 JSON 时处理异常，检查数据结构和版本。遇到旧数据损坏时保留原数据，不要静默清空或覆盖。
- 保存失败时明确告知用户，不假装保存成功；尽量保留页面上的当前内容并提醒备份。
- 不使用 localStorage.clear()，不修改其他 APP 的存储。
- 本地数据不等于云同步；清理浏览器数据、换浏览器、换地址可能无法看到原数据。必须说明重要数据的备份方式。
- 不自动上传数据，不加入统计追踪，不把 API 密钥或账户密码写进前端代码。
- 用户输入用 textContent 等安全方式展示，不执行输入的脚本。

【交付说明】
- 用通俗中文说明：有哪些功能、哪些需要联网、数据保存在哪里、有什么限制。
- 列出全部文件及用途；区分“代码已经写好”和“已经实际测试通过”。
- 交付前检查打开页面、主要按钮、320px 窄屏、刷新后的状态；有存储功能时检查读写失败提示。没有实测的项目明确写待验证。
- 本次只制作我要求的代码；不要擅自接入小手机桌面、覆盖已有文件、上传 GitHub 或发布。

## 如何使用空白 HTML（零基础）

1. 把上述制作要求发给负责写代码的 AI，填上你要的 APP 功能即可；你不需要先自己改代码。
2. 如果对方需要基础文件，再提供同目录的 `html-app-template.html`。它是起点，不是功能成品。
3. 对方完成后，把完整 HTML 和所需素材交回来，先检查，再在你确认后接入对应入口。
4. 塔罗、日历、课程表要分别交付，不能用一个没有完成的入口冒充三个 APP 都已完成。

本模板不承诺离线可用：没有外部依赖只是离线运行的前提之一，页面和素材是否已缓存、能否离线打开仍需单独实现和验证。
